## Что сделано и что не успел

### Что сделано:
- **Экран «Матчи тура» (`MatchesScreen`)**:
  - Загрузка данных по сети с обработкой состояния загрузки (`ActivityIndicator`), ошибки с кнопкой «Повторить» и пустого списка.
  - Карточки матчей (`MatchCard`): хозяева и гости, их города, счёт матча (включая нулевой счёт `0:0`), дата и время начала с авто-конвертацией в локальный часовой пояс устройства, русскоязычные статусы с цветными бейджами.
  - Кнопка избранного (звёздочка `FavoriteButton`) на каждой карточке с корректной синхронизацией состояния.
- **Фильтрация и поиск**:
  - Фильтры над списком: **Все / Предстоящие / Завершённые** со счётчиками количества матчей в табах.
  - Поиск команд и городов в реальном времени (`SearchBar`) с кнопкой быстрой очистки.
- **Обновление данных**:
  - Поддержка pull-to-refresh на мобильных устройствах.
  - Явная кнопка «↻ Обновить» в шапке экрана (удобно для веб-версии, где нет жеста свайпа).
  - Корректно работающий компонент `UpdatedAgo` («Обновлено N сек назад»), сбрасывающийся при каждом запросе.
- **Исправление багов коллеги**:
  - Устранены ошибки в `useFavorites.ts` и `UpdatedAgo.tsx`.
- **Типизация**:
  - Полная типизация моделей данных и компонентов, успешная проверка через `npx tsc --noEmit`.

### Что не успел:
- Сохранение избранного в персистентное хранилище (`AsyncStorage`) между сессиями (оставлено в памяти по условию исходного хука).

## Решения

- **Куда отнесены матчи с другими статусами (`live`, `postponed`):**
  - Статус `live` (матч идёт прямо сейчас) отнесён к **«Предстоящие»** (активные / не завершённые матчи тура). Пользователь, заходящий в раздел актуальных событий, ожидает видеть текущие матчи, исход которых ещё не определён. В карточке такой матч визуально выделяется бейджем с минутой игры.
  - Статус `postponed` (перенесён) также отнесён к **«Предстоящие»**, поскольку этот матч турнира не был сыгран и состоится в будущем (дата уточняется).
  - В категории **«Завершённые»** отображаются строго матчи со статусом `finished`.
- **Неочевидные случаи в данных и их обработка:**
  1. `startsAt: null` у перенесённого матча (`m7`, Балтика — Факел). Прямой вызов `new Date(match.startsAt)` привёл бы к ошибке `Invalid Date` или дате 1970 года. Сделана явная проверка: при отсутствии даты выводится «Дата уточняется».
  2. Нулевой счёт (`0:0` у матча `m2`, Локомотив — ЦСКА). Так как `0` в JavaScript является falsy-значением, проверка вида `if (match.score?.home)` ошибочно скрыла бы счёт. Проверка сделана строго: `match.score !== null && match.score !== undefined`.
  3. Часовой пояс устройства: даты из ISO UTC строки (`2026-10-11T13:00:00Z`) форматируются через стандартные функции `toLocaleDateString` и `toLocaleTimeString` с русской локалью, что гарантирует точное отображение в местном часовом поясе клиента.
  4. Адрес в `src/config.ts`: в исходном файле содержался шаблон-заглушка `OWNER/REPO`, выдающий 404. Адрес обновлён на актуальный рабочий URL репозитория на GitHub.

## Баги из части 2

1. **Звёздочки (`FavoriteButton` / `useFavorites.ts`):**
   - *Почему так происходило:*
     1. В `isFavorite` использовалось `Boolean(favorites.indexOf(id))`. Если элемент не найден в массиве, `indexOf` возвращает `-1`, а `Boolean(-1)` в JavaScript равен `true`. Если же элемент находился на первой позиции (`index === 0`), `Boolean(0)` возвращал `false`. Из-за этого звёздочка по умолчанию горела у всех не добавленных матчей.
     2. В функции `toggle` массив `favorites` мутировался напрямую через `.push()` и `.splice()`, после чего в `setFavorites(favorites)` передавалась та же самая ссылка. React сравнивает объекты по ссылке (`Object.is`) и пропускал рендер из-за отсутствия изменения ссылки на массив.
   - *Что исправили:* использовали метод `favorites.includes(id)` для точной проверки наличия и переписали `toggle` на иммутабельное обновление с созданием новой копии массива (`setFavorites(prev => ...)`).

2. **«Обновлено N сек назад» (`UpdatedAgo.tsx`):**
   - *Почему так происходило:*
     1. В `useEffect` был передан пустой массив зависимостей `[]`. Из-за этого эффект запускался только при первом монтировании компонента и игнорировал изменение пропа `since` при последующих обновлениях данных.
     2. Внутри коллбэка интервала использовалось устаревшее замыкание `setSeconds(seconds + 1)` (в замыкании `seconds` всегда был 0, поэтому счётчик застревал на 1).
     3. Не возвращалась функция очистки `clearInterval`, что приводило к утечке памяти и наслоению фоновых интервалов.
   - *Что исправили:* вычисляем прошедшие секунды динамически от текущего времени (`Date.now() - since.getTime()`), добавили `since` в зависимости эффекта для мгновенного сброса при новом обновлении и добавили `clearInterval` в cleanup-функцию эффекта.
